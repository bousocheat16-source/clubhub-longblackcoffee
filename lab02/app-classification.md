# Lab-02 · Classification of five applications

Version 1.0 · 2026-11-01 · Team: longblackcoffee

| # | Application | Kind | Type(s) | Where the code runs, how it is delivered | Architecture | Top 3 qualities (why) | Filled by |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Advanced Bank of Asia (ABA) | Application Software | Mobile native, cross-platform, enterprise, data-intensive | Front-end runs on mobile phone (iOS / Android), back-end runs on bank servers; delivered via Apple App Store / Google Play Store | Client-server; evidence: app opens with cached local data but requires active internet connection to execute financial transactions via backend APIs | Security (if authentication fails, unauthorized users can access accounts and transfer funds), Availability (if the backend is down, users cannot make urgent KHQR payments or transfers), Performance (if API latency is high, payment confirmation times out at checkouts) | @Vathanabe |
| 2 | Telegram | Application Software | Mobile native, desktop, web SPA, cloud SaaS, data-intensive | IOS / Android (App Store / Google Play), desktop app (download from telegram.org), browser SPA (web.telegram.org), Telegram servers in data centers; chats cached on the device, so old messages still open offline | client-server; phone, desktop and web clients call the same back-end (new phone login shows the full chat history, because it lives on the servers) | availability (when Telegram goes down, chats and groups go quiet), performance (if a message takes more than a second to show up, the chat feels broken), security (if someone gets hold of your login code, they can read your private chats and message your friends pretending to be you) | @Choulita |
| 3 | ABS controller in a car (Ford Territory 2025) | System Software | Embedded real-time | Runs on an ECU (Electronic Control Unit) programmed in the car. The program is installed directly from the car factory | Embedded control loop. Evidence: The software constantly loops to monitor wheel speed sensors and immediately adjusts brake pressure when it detects a slip. | Safety: If the software fails or calculates incorrectly during sudden braking, the vehicle could skid out of control and cause an accident. Performance: If the system is too slow to process the sensor data, it will not pulse the brakes fast enough to maintain traction. Availability: If the ABS controller unexpectedly goes offline while driving, the driver loses a critical anti-lock braking function during an emergency. | @bousocheat16-source |
| 4 | Moodle at ITC | Application Software | Web MPA, Enterprise | Runs in the user's web browser and on the school's servers. Reaches the user via a URL entered in the browser. | Client-server. Evidence: Students log in through a web browser to download files and submit assignments hosted centrally on the school's server. | Availability: If Moodle is down during an online quiz, students cannot submit their answers. Security: If the system is breached, students' private grades could be leaked or altered. Usability: If the interface is too confusing, students might accidentally upload their homework to the wrong submission box. | @Sereyboth-cmd |
| 5 | Game: Roblox | Application Software | Game, Cross-platform, cloud SaaS | The app runs on a user's device (by downloading from App Store or Play Store or from the website) | Rely on client-server, must have internet to play games and interact with others | Performance: If the game has a high latency then most users' device won't be able to run Security: If the platform is breached, users may have their account stolen and loses a lot of their value items in-game Availability: If the game's server shut down, millions of users won't be able to play | @Lyfang519 |

Biggest difference we found: Unlike Moodle, Telegram, ABA, and Roblox, which is the application software type, they rely on network availability and remote server, the ABS controller in a car operates and responds locally.
